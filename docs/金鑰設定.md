# 金鑰填寫流程

系統用到的金鑰、密碼一共 9 種。原則：

- **金鑰不要貼在聊天、LINE、Email 裡，也不要 commit 進 git。** 直接在下面寫的地方填。
- 標「機密」的只能放在伺服器端，標「公開」的會出現在網頁原始碼裡（本來就設計成可以公開）。
- 金鑰外流或懷疑外流：到發金鑰的地方作廢、重發一把，再照這份文件重填。

## 總表

| # | 金鑰 | 機密？ | 去哪裡拿 | 填在哪裡 |
|---|---|---|---|---|
| 1 | Supabase 專案網址 | 公開 | Supabase 後台 → Project Settings → API | Vercel、`web/.env.local`、上傳程式 |
| 2 | Supabase Publishable key（`sb_publishable_…`） | 公開 | Supabase 後台 → Project Settings → API Keys | Vercel、`web/.env.local` |
| 3 | Supabase Secret key（`sb_secret_…`） | **機密** | 同上（按 Reveal） | Vercel、`web/.env.local`（不能加 `NEXT_PUBLIC_`） |
| 4 | Gemini API Key | **機密** | 甲方的 Google AI Studio | Supabase Edge Function Secrets |
| 5 | 排程密鑰 CRON_SECRET | **機密** | 自己產生 | Supabase Edge Function Secrets ＋ Supabase Vault |
| 6 | 手機推播金鑰 VAPID（公鑰＋私鑰） | 公鑰公開、私鑰**機密** | 自己產生 | 公鑰：Vercel＋Edge Secrets；私鑰：只放 Edge Secrets |
| 7 | 上傳金鑰（`uc_up_…`） | **機密** | 系統「系統設定 → 新增上傳金鑰」 | 常駐電腦 `config.json` |
| 8 | 備份金鑰（`uc_bk_…`） | **機密** | 系統「系統設定 → 新增備份金鑰」 | 常駐電腦 `config.json` |

## 步驟

### 第 1 步：Supabase 專案的 3 個值（#1～#3）

**1-1 建立專案**（只做一次）
1. 登入 <https://supabase.com/dashboard> → **New project**。
2. Organization 選我們的組織；Project name 填 `ucode-receipt`（看得懂就好）。
3. **Database Password**：按 Generate 產生一組，**存到密碼管理工具**（之後 `supabase db push` 要用，畫面關掉就看不到了）。
4. **Region**：選 **Northeast Asia (Tokyo)**（合約寫日本機房）。
5. 展開 Security 設定，三個勾選照 CLAUDE.md：Enable Data API ✅、Automatically expose new tables ❌、Enable automatic RLS ✅。
6. 按 Create new project，等 1～2 分鐘建好。

**1-2 Project URL（#1，公開）**
- 最穩的找法：看瀏覽器網址列 `supabase.com/dashboard/project/abcdefghijkl`，最後那串就是 project ref，Project URL ＝ `https://abcdefghijkl.supabase.co`。
- 或在專案頁面上方按 **Connect**，對話框裡會列出 Project URL。（後台選單常改名，舊版在 Settings → API，新版在 Settings → Data API。）
- 結尾不要帶 `/rest/v1`。

**1-3 Publishable key（#2，公開）**
1. 左下 **Project Settings → API Keys**。
2. 「Publishable key」區塊有一把 `sb_publishable_…`，按旁邊的複製。如果是空的，按 **Create new API keys** 產生。
3. 這把會出現在網頁原始碼裡，本來就可以公開；資料安全靠資料庫的 RLS 權限。

**1-4 Secret key（#3，機密）**
1. 同一頁往下 **Secret keys** 區塊 → **Add new secret key**，名稱填 `vercel-web`（用途寫清楚，之後要作廢比較好認）。
2. 建好後按 **Reveal** → 複製 `sb_secret_…`。
3. 這把等於資料庫的萬能鑰匙（可以繞過所有權限），**只能填在 Vercel 和自己電腦的 `web/.env.local`**，不能貼到任何地方、不能加 `NEXT_PUBLIC_`。
4. 建第一個老闆帳號的 `scripts/create_owner.ts` 也用這把（只在自己電腦執行一次）。

**1-5 不要動的地方**
- 同一頁的 **Legacy API keys（anon、service_role）先不要停用**：雲端程式（Edge Functions）目前用 Supabase 自動提供的 `SUPABASE_SERVICE_ROLE_KEY`，停用舊金鑰可能讓辨識佇列停掉。部署後我會確認雲端程式能改用新金鑰，再決定要不要停用。
- Edge Functions 不用自己填 Supabase 的網址和金鑰，Supabase 會自動提供。

**1-6 讓我們的電腦能部署（乙方電腦做一次）**
```
npx supabase login                         # 開瀏覽器登入 Supabase
npx supabase link --project-ref abcdefghijkl   # 會問 1-1 的 Database Password
```

### 第 2 步：Gemini API Key（#4，甲方帳號）

和業主一起操作（帳號、付款人是業主）：

1. 用業主的 Google 帳號登入 <https://aistudio.google.com> → 左側 **Get API key** → Create API key。
2. 同一頁設定付款（Billing），確認是付費方案（免費方案有每日上限，500 張會卡住）。
3. 請業主把我們的 Google 帳號加為專案成員，之後才看得到用量與錯誤。

### 第 3 步：自己產生的金鑰（#5、#6）

在自己電腦的終端機執行（產生的值只存在你的電腦，不會送出去）：

```
openssl rand -hex 32                          # → CRON_SECRET
npx web-push@3.6.7 generate-vapid-keys        # → VAPID Public Key、Private Key
```

### 第 4 步：填進 Supabase（#4、#5、#6）

1. 在專案資料夾建一個 `supabase/.env.secrets`（已在 .gitignore，不會進 git），內容：
   ```
   GEMINI_API_KEY=第 2 步的 Gemini Key
   CRON_SECRET=第 3 步的 CRON_SECRET
   VAPID_PUBLIC_KEY=第 3 步的 Public Key
   VAPID_PRIVATE_KEY=第 3 步的 Private Key
   VAPID_SUBJECT=mailto:你的 Email
   ```
2. 執行 `npx supabase secrets set --env-file supabase/.env.secrets`。
   （也可以在後台 Edge Functions → Secrets 逐一新增，結果一樣。）
3. 排程需要的專案網址與排程密鑰，由雲端程式自己寫進 vault，不用手動（見 `docs/部署.md` 第 1 節第 5 步）。
4. 填完可以把 `supabase/.env.secrets` 刪掉，或留著當備份（不要傳給別人）。

### 第 5 步：填進 Vercel（#1、#2、#3、#6 公鑰）

Vercel 專案 → **Settings → Environment Variables**，新增 4 個（Production、Preview 都勾）：

```
NEXT_PUBLIC_SUPABASE_URL=第 1 步的 Project URL
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=第 1 步的 Publishable key
SUPABASE_SECRET_KEY=第 1 步的 Secret key
NEXT_PUBLIC_VAPID_PUBLIC_KEY=第 3 步的 VAPID Public Key
```

填完要 **Redeploy** 一次才會生效。

### 第 6 步：本機開發（選做）

`web/.env.example` 複製成 `web/.env.local`（已在 .gitignore），填同第 5 步的 4 個值，就能用 `npm run dev` 連到正式資料庫測試。

### 第 7 步：常駐電腦（#7、#8，到場安裝時）

1. 用老闆帳號登入系統 → **系統設定 → 常駐電腦與資料備份**。
2. 按「新增上傳金鑰」、取名（例：櫃台電腦）→ 畫面顯示金鑰，**只會出現這一次**，按「複製」。
3. 打開常駐電腦上的 `config.json`（範本 `uploader/config.example.json`），貼到 `upload_token`。
4. 同樣按「新增備份金鑰」，貼到 `backup_token`。
5. `api_url` 填 `https://xxxx.supabase.co/functions/v1/device-api`；`web_url` 填系統網址。
6. 電腦遺失、更換或懷疑外流：在同一頁按「停用」，再新增一把重填。

## 填完怎麼確認

| 檢查 | 正常的樣子 |
|---|---|
| 打開系統網址 | 出現登入頁；登入後看得到處理總覽 |
| 常駐電腦執行上傳程式 | 工作列綠色圓點；處理總覽「掃描上傳程式」顯示最近回報時間 |
| 掃一張單據 | 幾分鐘內出現在「掃描與辨識」，批次辨識完成後有結果 |
| 手機加入主畫面 → 按「開啟手機通知」 | 下一批辨識完成時手機跳出通知 |
